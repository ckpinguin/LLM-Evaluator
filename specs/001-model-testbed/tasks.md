# Tasks: Model Testbed

**Input**: Design documents from `/specs/001-model-testbed/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md

**Tests**: Included. The spec does not require TDD, but the constitution ("Development Workflow &
Quality Gates") requires behavior to be verified with simple, readable tests, and plan.md defines
offline unit tests plus `network`-marked end-to-end tests. Write each story's tests first and
make sure they fail before implementing that story.

**Organization**: Tasks are grouped by user story so each story can be implemented, tested, and
demonstrated on its own.

**Rules for every code task** (constitution principles III and IV, plan.md):

- Every module starts with a docstring explaining its role; every public function has a
  docstring; non-obvious steps get a comment explaining *why*.
- Import heavy libraries (`torch`, `transformers`, `sentence_transformers`, `lm_eval`, `datasets`,
  `sklearn`) **inside the functions that use them**, never at module level, so `testbed --help`
  and `testbed models` stay fast.
- Core modules never print. Only `src/testbed/cli.py` writes to the terminal. User-fixable
  problems raise `TestbedError` with a plain-language message.
- Always pass `trust_remote_code=False` (or rely on its default) and never load `*.bin` weights.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: Which user story this task belongs to (US1–US4)

## Path Conventions

Single project with `src/` layout at the repository root: `src/testbed/`, `tests/`. See
plan.md "Project Structure".
